# AInvest Agent v5.1.1 技术方案：Vectra 主进程迁移

> 版本：v5.1.1  
> 日期：2026-06-11  
> 类型：架构修复（Bugfix）  
> 优先级：P0 —— 阻塞 v5.1 集成测试通过

---

## 一、问题描述

v5.1 将 embedding 服务从本地 WASM 迁移到智谱云端 API 后，**向量存储层（Vectra）在 Electron 渲染进程中初始化失败**。

### 1.1 根因

- Vectra（v0.15.0）是纯 Node.js 库，内部依赖 `fs.promises` 进行文件系统操作
- Electron 渲染进程配置 `nodeIntegration: false`，Vite 对 `fs` 进行 browser polyfill
- 该 polyfill 缺失 Node.js v14.14.0 引入的 `fs.promises.rm` 方法
- Vectra 的 `LocalFileStorage.deleteFolder` 在 `LocalIndex.createIndex()` 时调用 `fs.promises.rm`，导致初始化抛错：
  ```
  TypeError: promises_1.default.rm is not a function
  ```

### 1.2 影响范围

| 功能 | 影响 |
|------|------|
| 向量索引初始化 | ❌ 完全失败，任何 `getIndex()` 调用抛错 |
| 语义检索 (`searchMemories`) | ❌ 每次聊天后报错 `Index does not exist`，降级返回空数组 |
| 记忆归档 (`archiveSession`) | ⚠️ 已临时绕过（v5.1 bugfix），向量写入跳过，偏好提取仍可用 |
| 记忆管理面板 | ❌ 打开即报错，无法添加/查询向量 |
| 长期记忆效果 | ❌ 语义检索完全失效，跨 Session 关联能力丧失 |

### 1.3 为什么必须在 v5.1.1 修复

- v5.1 的核心卖点是"云端 embedding + 本地向量记忆"
- 当前向量索引完全不可用，导致长期记忆功能名存实亡
- 临时绕过方案（跳过向量归档）只能让测试不报错，无法验证记忆系统价值

---

## 二、目标

将 Vectra 向量数据库操作从**渲染进程**迁移到**主进程**，通过 IPC 暴露接口，彻底根治 `fs.promises.rm` 兼容性问题，恢复完整的向量记忆功能。

---

## 三、架构变更

### 3.1 迁移前（v5.1 当前）

```
渲染进程 (Chromium)
├── ChatPanel / MemoryDebugPanel
├── memoryArchive.ts
├── vectorStore.ts  ←── 直接 import 'vectra' ❌
│   └── LocalIndex (使用 fs polyfill，缺失 rm)
└── embeddingService.ts (HTTP API，正常)
```

### 3.2 迁移后（v5.1.1）

```
主进程 (Node.js)
├── services/vectorStore.ts  ←── 直接 import 'vectra' ✅
│   └── LocalIndex (原生 fs，完整支持 rm)
├── ipcHandlers/memory.ts    ←── IPC 路由层
└── index.ts                 ←── 注册 IPC

渲染进程 (Chromium)
├── ChatPanel / MemoryDebugPanel
├── memoryArchive.ts
├── vectorStore.ts           ←── 纯 IPC 代理，零 Node 依赖
└── embeddingService.ts (HTTP API，正常)
```

## 五、IPC 接口设计

### 5.1 Preload 暴露接口

```typescript
export interface MemoryAPI {
  insertItem: (record: VectorRecord) => Promise<void>
  insertItems: (records: VectorRecord[]) => Promise<void>
  queryItems: (vector: number[], topK: number) => Promise<RawQueryResult[]>
  deleteItem: (id: string) => Promise<void>
  getStats: () => Promise<{ itemCount: number; path: string }>
  listItems: () => Promise<VectorRecord[]>
  getItem: (id: string) => Promise<{ id: string; vector: number[]; metadata: Record<string, unknown> } | null>
  upsertItem: (id: string, vector: number[], metadata: Record<string, unknown>) => Promise<void>
}
```

### 5.2 IPC Channel 映射

| Channel | 方向 | 参数 | 返回值 |
|---------|------|------|--------|
| `memory:insertItem` | R→M | `VectorRecord` | `void` |
| `memory:insertItems` | R→M | `VectorRecord[]` | `void` |
| `memory:queryItems` | R→M | `vector: number[], topK: number` | `RawQueryResult[]` |
| `memory:deleteItem` | R→M | `id: string` | `void` |
| `memory:getStats` | R→M | — | `{ itemCount, path }` |
| `memory:listItems` | R→M | — | `VectorRecord[]` |
| `memory:getItem` | R→M | `id: string` | `item \| null` |
| `memory:upsertItem` | R→M | `id, vector, metadata` | `void` |

> R=Renderer, M=Main

### 5.3 关键类型补充

```typescript
// 新增到 src/shared/types/memory.ts
export interface RawQueryResult {
  item: {
    id: string
    vector: number[]
    metadata: Record<string, unknown>
  }
  score: number
}
```

## 六、详细实现步骤

### 步骤 1：主进程向量服务 `src/main/services/vectorStore.ts`

复制渲染进程 `vectorStore.ts` 的核心逻辑到主进程，做以下调整：

1. **路径计算**：使用 `app.getPath('userData')` + `path.join`，不再依赖 `window.appAPI`
2. **完整 Node fs**：`fs.promises.rm` 原生可用，无需 polyfill
3. **互斥锁保留**：`beginUpdate`/`endUpdate` 的并发保护在主进程仍然需要
4. **新增方法**：
   - `getItem(id)`：供合并逻辑查询旧记录
   - `upsertItem(id, vector, metadata)`：供合并逻辑更新记录，内部封装 `beginUpdate`/`endUpdate`

### 步骤 2：主进程 IPC Handler `src/main/ipcHandlers/memory.ts`

```typescript
import { ipcMain } from 'electron'
import * as vectorStore from '../services/vectorStore'

export const registerMemoryIPC = (): void => {
  ipcMain.handle('memory:insertItem', async (_event, record) => {
    await vectorStore.insertItem(record)
  })
  ipcMain.handle('memory:insertItems', async (_event, records) => {
    await vectorStore.insertItems(records)
  })
  ipcMain.handle('memory:queryItems', async (_event, vector, topK) => {
    return await vectorStore.queryItems(vector, topK)
  })
  // ... 其余 handler
}
```

### 步骤 3：主进程入口注册 `src/main/index.ts`

```typescript
import { registerMemoryIPC } from './ipcHandlers/memory'

app.whenReady().then(async () => {
```

### 步骤 5：渲染进程 `vectorStore.ts` 重写

**完全移除 `import { LocalIndex } from 'vectra'`**，改为 IPC 代理：

```typescript
export const addVector = async (record: VectorRecord): Promise<void> => {
  await window.memoryAPI.insertItem(record)
  logInfo('memory', 'vectorStore.added', { id: record.id })
}

export const addVectors = async (records: VectorRecord[]): Promise<void> => {
  await window.memoryAPI.insertItems(records)
  logInfo('memory', 'vectorStore.batchAdded', { count: records.length })
}

export const queryVectors = async (
  vector: number[],
  options: VectorQueryOptions = {}
): Promise<VectorQueryResult[]> => {
  const { topK = 5, minScore = 0.7 } = options
  const results = await window.memoryAPI.queryItems(vector, topK)
  return results
    .filter((r) => r.score >= minScore)
    .map((r) => ({
      id: r.item.id,
      score: r.score,
      metadata: r.item.metadata as VectorRecord['metadata'],
    }))
}

export const removeVector = async (id: string): Promise<void> => {
  await window.memoryAPI.deleteItem(id)
  logInfo('memory', 'vectorStore.removed', { id })
}

export const getStoreStats = async () => {
  return await window.memoryAPI.getStats()
}

export const listAllItems = async (): Promise<VectorRecord[]> => {
  return await window.memoryAPI.listItems()
}

// 新增：供 memoryArchive.ts 合并逻辑使用
export const getVectorItem = async (id: string) => {
  return await window.memoryAPI.getItem(id)
}

export const upsertVector = async (
  id: string,
  vector: number[],
  metadata: VectorRecord['metadata']
): Promise<void> => {
  await window.memoryAPI.upsertItem(id, vector, metadata)
}
```

> **注意**：渲染进程的互斥锁（`Mutex`）可以删除，因为并发控制已在主进程处理。

## 七、数据兼容性

### 7.1 索引文件位置

迁移前后索引路径一致：
```
%userData%/ainvest/vector-memory/
```

主进程和渲染进程通过 `window.appAPI.getUserDataPath()` 获取的路径相同（都指向 `app.getPath('userData')/ainvest`），因此已有的索引文件无需迁移。

### 7.2 索引格式兼容性

Vectra 的索引文件格式不变，主进程和渲染进程使用的是同一个 `vectra` 版本（v0.15.0），因此：
- **已有的 `vector-memory/` 索引可以直接继续使用**
- 无需重建索引
- 维度保持 512（与 embedding-3 一致）

## 八、风险与回滚

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| IPC 调用延迟增加 | 低 | 向量操作延迟从 ~1ms 增加到 ~5ms | 对用户体验无感知，批量接口减少往返 |
| 主进程 IPC handler 并发冲突 | 中 | 并发归档/查询可能损坏索引 | 主进程保留 `Mutex` 互斥锁 |
| IPC 参数序列化失败 | 低 | `VectorRecord` 包含不可序列化字段 | 确保 metadata 为纯 JSON 对象 |
| 构建后主进程找不到 `vectra` | 低 | electron-builder 打包失败 | `vectra` 已在 `dependencies` 中，electron-vite 会自动 externalize |

### 回滚方案

如需回滚到渲染进程方案（不推荐）：
1. 恢复渲染进程 `vectorStore.ts` 到 v5.1 版本（直接 import Vectra）
2. 删除主进程 `services/vectorStore.ts` 和 `ipcHandlers/memory.ts`
3. 恢复 preload 和主进程入口的注册代码
4. 重新启用渲染进程 `vectorStore.ts` 中的 `fs.promises.rm` polyfill（如果找到可行方案）
