# AInvest CLI Agent 桌面应用 v2 PRD

## 1. 产品概述与背景

AInvest CLI Agent 是一款面向投资研究的桌面 Agent 工作台。v2 阶段核心目标是将 Agent 从 **Mock 回复 + 硬编码意图识别** 升级为 **大模型驱动 + 动态记忆**，使聊天窗口真正可用。

**产品定位**：简约现代的金融投研平台，参考 Codex IDE 风格，强调工具化、专业化、可扩展性。

**v2 核心变化**：
- Agent 回复由大模型（Kimi）实时生成，不再是固定 Mock 文本
- 意图识别由大模型完成，支持更复杂的自然语言理解
- 引入短期记忆（Session 上下文）和长期记忆（用户偏好提炼）
- 用户可自主配置大模型 API 参数

---

## 2. v2 MVP 目标

完成 Agent 聊天窗口的可用升级，重点验证以下假设：

1. **大模型集成**：能否稳定接入 Kimi API，实现流式对话生成
2. **意图识别**：大模型能否准确将用户输入分类到预设意图类型
3. **工具调用闭环**：大模型能否在需要时正确触发工具调用，并将结果整合到回复中
4. **记忆系统**：短期记忆（Session 上下文）和长期记忆（用户偏好）能否正确加载和更新
5. **配置可用**：用户能否顺利配置 API Key 并正常使用

### v2 新增用户故事

#### 用户故事 7：配置大模型
> 作为用户，我想要在应用中配置自己的 Kimi API Key，以便 Agent 能够调用大模型进行智能回复。

**场景**：用户首次打开应用，点击设置 → 大模型配置，输入 API Key，选择模型（moonshot-v1-8k/32k/128k），点击保存。应用验证 Key 有效性后，Agent 开始使用大模型回复。

**验收标准**：
- [ ] 设置页存在"大模型配置"区块
- [ ] 支持输入 API Key（带显示/隐藏切换）
- [ ] 支持选择模型版本（8k/32k/128k）
- [ ] 支持配置 Temperature（0-2，默认 0.7）
- [ ] 保存后即时生效，无需重启
- [ ] API Key 无效时给出明确错误提示

#### 用户故事 8：体验智能 Agent 对话
> 作为用户，我想要 Agent 能够像专业投研助手一样自然回复，而不是机械的固定文本。

**场景**：用户输入"茅台最近怎么样"，Agent 理解用户可能在问行情，也可能在问新闻或基本面，通过大模型生成自然语言回复："贵州茅台近期表现较为稳健，今日报价 1688.00 元，上涨 2.5%。需要我为您查看相关新闻或进行技术分析吗？"

**验收标准**：
- [ ] Agent 回复由大模型实时生成，非固定 Mock 文本
- [ ] 回复为流式输出，逐字显示在聊天窗口
- [ ] 回复中可包含工具调用触发（如自动展示行情卡片）
- [ ] 回复风格专业、符合金融投研语境

#### 用户故事 9：Agent 记住当前对话上下文
> 作为用户，我想要 Agent 记住我们在当前 Session 里聊过什么，以便我可以追问而不需要重复背景。

**场景**：用户先问"茅台今天怎么样"，Agent 展示了行情。用户接着问"那新闻呢"，Agent 能理解"那"指代茅台，直接展示贵州茅台的相关新闻，无需用户重复股票名称。

**验收标准**：
- [ ] 同一 Session 内，Agent 能引用之前的对话内容
- [ ] 用户指代（如"那"、"它"）能被正确解析
- [ ] 上下文保留最近至少 10 轮对话
- [ ] 切换 Session 后上下文独立，互不干扰

#### 用户故事 10：Agent 记住我的投资偏好
> 作为用户，我想要 Agent 记住我的风险偏好和关注板块，以便后续对话能更贴合我的需求。

**场景**：用户在某次对话中多次询问白酒和新能源板块。次日打开应用，新 Session 中用户问"今天有什么值得关注的机会"，Agent 主动推荐白酒和新能源板块的动态，因为长期记忆显示用户关注这些板块。

**验收标准**：
- [ ] 系统能自动从对话中提炼用户偏好
- [ ] 偏好包括：风险偏好、关注板块、常问问题类型
- [ ] 新 Session 自动加载已有偏好作为系统提示词
- [ ] 用户可在设置中查看和手动修改偏好
- [ ] 提供"总结今日偏好"Mock 按钮作为手动触发入口

#### 用户故事 11：通过自然语言进行复杂查询
> 作为用户，我想要用更自然的语言表达复杂需求，而不需要记忆固定的指令格式。

**场景**：用户输入"帮我看看最近一周涨得最好的新能源股票，再对比一下白酒板块的龙头"，Agent 识别这是多意图复合请求，分别调用行情查询工具，最后整合结果给出对比分析。

**验收标准**：
- [ ] 支持模糊、口语化的自然语言输入
- [ ] 支持复合意图（一个句子包含多个请求）
- [ ] 对无法识别的意图给出友好提示，而不是静默失败

## 4. 核心功能模块

### 4.1 Agent 引擎（v2 升级）

**现状**：硬编码正则意图识别 + Mock 固定回复
**目标**：大模型驱动 + Function Calling 工具调用 + 自然语言生成

**核心流程**：
```
用户输入
  → 意图识别（LLM 分类 + 正则兜底）
  → 构建上下文（系统提示词 + 长期记忆 + Session 历史）
  → 调用 LLM 流式生成
  → 检测工具调用指令
  → 执行工具 / 直接展示文本回复
  → 工具结果回传 LLM → 生成最终自然语言回复
```

**意图类型定义**：
| 意图类型 | 说明 | 对应工具 |
|---------|------|---------|
| `market.query` | 行情查询 | 行情查询工具 |
| `news.search` | 新闻检索 | 新闻检索工具 |
| `strategy.backtest` | 策略回测 | 策略回测工具 |
| `stock.profile` | 股票档案 | 个股详情工具 |
| `general.chat` | 通用聊天（不需要工具） | 无 |
| `session.manage` | Session 管理（新建、切换、重命名、删除） | 无 |
| `preference.update` | 更新偏好设置 | 无 |
| `unknown` | 无法识别 | 无（给出友好提示） |

### 4.2 大模型配置

**配置项**：
| 配置项 | 类型 | 默认值 | 说明 |
|-------|------|-------|------|
| API Key | string | "" | Kimi API Key，必填 |
| Base URL | string | "https://api.moonshot.cn/v1" | API 基础地址 |
| 模型 | enum | "moonshot-v1-8k" | 可选：8k / 32k / 128k |
| Temperature | number | 0.7 | 0-2，控制回复创造性 |

**存储位置**：`localStorage`（v2 阶段），后续迭代可加密

**验证逻辑**：保存时发送一条简单请求验证 Key 有效性

### 4.3 意图识别器

**策略**：LLM 为主 + 本地正则兜底

**流程**：
1. 本地正则快速匹配（零成本）
2. 置信度 > 0.9 直接返回
3. 否则调用 LLM 分类（带最近 3 轮上下文）
4. LLM 超时/失败 → 正则兜底

**兜底规则（保留 v1 正则）**：
- `/行情|查.*股|股价|涨跌/` → `market.query`
- `/新闻|公告|资讯/` → `news.search`
- `/回测|策略|MA|均线/` → `strategy.backtest`
- `/档案|基本面|公司简介/` → `stock.profile`

### 4.4 短期记忆（Session 上下文）

**机制**：每个 Session 的对话历史自动维护为 LLM 消息格式

**上下文窗口管理**：
- 保留最近 **10 轮**完整对话
- 超过时，早期对话用 LLM 压缩为摘要（Nice-to-have）

**消息格式**：
```typescript
interface ChatMessage {
  role: 'system' | 'user' | 'assistant' | 'tool';
  content: string;
  tool_calls?: ToolCall[];
  tool_call_id?: string;
}
```

### 4.5 长期记忆（用户偏好提炼）

**存储位置**：`userData/ainvest/memory.json`

**数据结构**：
```typescript
interface UserMemory {
  riskPreference?: 'conservative' | 'moderate' | 'aggressive';
  watchedSectors?: string[];
  frequentQuestions?: string[];
  updatedAt: number;
}
```

**提炼时机**：
1. **手动触发**：用户点击"总结今日偏好"按钮（v2 MVP Mock 入口）
2. **自动触发**：每日定时（Nice-to-have，v2 可先写死为应用关闭时检查）

**提炼流程**：
```
收集当天所有 Session 对话
  → 构造提炼 Prompt
  → 调用 LLM（非流式）生成 JSON
  → 解析并合并到现有 memory（增量更新）
  → 保存到 memory.json
```

**记忆注入**：每个新 Session 开始时，将 memory 注入 System Prompt

### 4.6 工具调用（升级）

**模式**：类 Function Calling（与 OpenAI/Kimi 规范对齐）

**流程**：
```
LLM 输出工具调用 JSON
  → 前端解析并执行对应工具
  → 拿到结果 → 包装为 tool 消息回传 LLM
  → LLM 生成最终自然语言回复
```

**ToolCall 格式**：
```typescript
interface ToolCall {
  id: string;
  type: 'function';
  function: {
    name: string;       // 如 'market.query'
    arguments: string;  // JSON 字符串
  };
}
```

### 4.7 行情看板（v1 保留，无变更）

功能同 v1：左侧 40% 区域，包含行情总览、自选股列表、个股详情。

### 4.8 Session 管理（v1 保留，UI 无变更）

功能同 v1：右侧 20% 区域，支持新建、切换、重命名、删除 Session。

### 4.9 状态管理（v1 保留，扩展）

在 v1 的 `useChatStore`、`useSessionStore`、`usePreferenceStore` 基础上：
- `useChatStore`：扩展 `getLLMContext()` 方法
- `usePreferenceStore`：扩展大模型配置字段
- 新增 `useMemoryStore`：管理长期记忆

## 5. 交互流程

### 5.1 首次配置大模型

```
打开应用
  → 检测无 API Key
  → 聊天面板顶部显示横幅提示："请配置大模型 API Key 以启用智能对话"
  → 用户点击"去配置"
  → 跳转设置页 → 大模型配置区块
  → 输入 API Key → 选择模型 → 保存
  → 验证成功 → 横幅消失 → Agent 可用
```

### 5.2 正常对话流程

```
用户输入
  → 添加到 UI（用户消息）
  → 构建上下文（System Prompt + 长期记忆 + Session 历史 + 当前输入）
  → 调用 LLM 流式生成
  → 逐字显示在聊天面板
  → 如检测到工具调用
       → 暂停文本输出
       → 展示工具调用卡片（loading）
       → 执行工具 → 展示工具结果
       → 工具结果回传 LLM
       → 继续流式生成最终回复
  → 完成 → 保存消息到 Session
```

### 5.3 每日偏好总结（Mock）

```
用户点击"总结今日偏好"按钮（Session 侧边栏底部）
  → 显示 loading
  → 收集当天所有 Session 对话
  → 调用 LLM 提炼偏好
  → 更新 memory.json
  → Toast 提示："今日偏好已更新"
  → 用户可在设置 → 个人偏好 中查看结果
```

## 7. 非功能需求

### 7.1 性能
- LLM 首次响应时间 < 3s（网络正常）
- 流式输出延迟 < 100ms/字
- 工具调用总耗时 < 5s（含 LLM 两次调用）

### 7.2 可靠性
- LLM 调用失败时给出明确错误提示，不卡死
- API Key 无效时引导用户重新配置
- 网络异常时支持重试 1 次

### 7.3 安全
- API Key 存储在 localStorage（v2 阶段，后续迭代加密）
- 不向任何第三方服务发送除 Kimi API 外的数据

### 7.4 兼容性
- Kimi API 为 OpenAI-compatible，后续迁移到其他模型成本低
- 工具调用格式与 OpenAI Function Calling 对齐

## 8. 错误处理

| 场景 | 处理方式 |
|-----|---------|
| API Key 无效 | Toast 提示"API Key 无效，请检查配置" |
| 网络超时 | Toast 提示"请求超时，请检查网络后重试" |
| LLM 返回异常 | 降级为正则意图识别 + 本地兜底回复 |
| 工具调用失败 | 展示错误信息，LLM 生成解释性回复 |
| 上下文过长 | 截断早期对话，保留最近 10 轮 |
