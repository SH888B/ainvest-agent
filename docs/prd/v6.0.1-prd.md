## 一、版本定位

v6.0.1 是 v6.0.0 的紧急修复版本，解决集成测试中发现的问题。核心原则：**最小改动、最大稳定**。

---

## 二、问题清单

### BUG-01：自动归档功能不稳定（P0）

**现象**：  
- 点击"新建 Session"按钮时，自动归档旧 Session 的异步逻辑与创建逻辑耦合，已导致 v6.0.0 中双重锁 Bug（`setCreating` + `createSession` 内部 `isCreating` 冲突）
- 归档失败静默吞错，用户无感知
- `archivedCount` 异步更新存在竞态

**决策**：**暂时关闭自动归档，改为纯手动按钮归档**。代码保留，通过配置开关控制。

**用户故事**：  
> 作为用户，当我点击"新建 Session"时，应该只创建新 Session，不触发任何后台归档操作。我只在主动点击"归档当前会话"时才归档。

---

### BUG-02：应用重启后显示上次 Session 的对话（P1）

**现象**：  
- 关闭应用再打开后，自动恢复到上次使用的 Session，显示旧的对话内容
- 用户期望：打开应用看到空白引导页，主动选择或新建 Session

**状态**：已在 v6.0.0 修复（`onRehydrateStorage` 重置 `currentSessionId`）

### BUG-03：设置弹窗关闭后输入框无法输入（P1）

**现象**：
- 在设置页清空所有偏好（弹窗提示成功），关闭弹窗后输入框无法输入
- 切换 Session 也无法输入

**复现步骤**：

2. 关闭弹窗/设置页
3. 回到聊天面板，点击输入框 → 无法输入

**影响**：v6 之前就存在，非本次引入

**用户故事**：
> 作为用户，当我关闭设置弹窗后，应该能立即在输入框中输入消息，不应该需要最小化窗口才能恢复。

### BUG-04：web.browse 工具参数提取失败（P0）

**现象**：
- 用户输入"帮我看看宁德时代最近有什么研报"
- 意图识别正确（`web.browse`），但参数提取返回空对象 `{}`
- 导致 `url` 为空字符串 → "错误：URL 格式不正确"
- 用户看到"工具调用失败"而非有用的信息

**根因**：
- `BROWSER_EXTRACTION_PROMPT` 要求 LLM 从自然语言**构造完整 URL**
- LLM 不一定知道目标网站的 URL 格式（如雪球的股票页面路径）
- `extractToolArgs` 返回 `{}` 时无本地兜底，直接传入空 URL 执行

**影响**：web.browse 工具几乎不可用

**用户故事**：
> 作为用户，当我问"帮我看看宁德时代最近有什么研报"时，Agent 应该能自动搜索相关金融网站并返回有用信息，而不是报"URL 格式不正确"。

**与主流方案的差距**：
- 主流方案（OpenAI WebSearchTool、Tavily）：LLM 生成**搜索关键词**，搜索引擎返回多源聚合结果
- 我们当前：LLM 构造**完整 URL**，CDP 访问单一页面
- 需要重构为"搜索优先"模式

### BUG-05：zustand selector 空数组引用导致无限 re-render（P0，已修复）

**现象**：应用启动后直接白屏崩溃，Console 报 `Maximum update depth exceeded`

**根因**：`useChatStore((state) => ... || [] : [])` 中 `|| []` 每次返回新数组引用 → zustand 判定状态变化 → 无限 re-render

**修复**：用模块级常量 `EMPTY_MESSAGES` + `??` 代替 `|| []`

**状态**：已修复

### BUG-06：新建 Session 按钮无响应（P0，已修复）

**现象**：点击"新建 Session"按钮，系统毫无反应

**根因**：组件先调用 `setCreating(true)`，然后 `createSession()` 内部检查 `isCreating` 发现已是 `true`，返回 `null`

**修复**：移除 `setCreating` action，`isCreating` 完全由 `createSession()` 内部管理

**状态**：已修复

### BUG-07：CDP SPA 页面内容提取返回空（P0）

**现象**：
- 用户输入"帮我看看宁德时代最近有什么研报"
- 意图识别正确（`web.browse`），搜索 URL 构造成功（`https://xueqiu.com/k?q=宁德时代研报`）
- 但 CDP 提取结果 `textLength: 0`
- 用户看到"看起来之前的搜索结果未能成功提取内容"

**根因**：
- `browserCDP.ts` 在 `did-finish-load` 事件后只等待固定 500ms
- SPA 页面（如雪球搜索页）的 `did-finish-load` 在初始 HTML 加载完成时触发，但 JS 渲染实际内容需要更长时间
- 500ms 内 JS 未完成渲染 → `document.body.innerText.length === 0`

**修复**：将固定延迟改为智能轮询——每 500ms 检查 `document.body.innerText.length`，内容出现即提前返回，最长等待 5000ms

**用户故事**：
> 作为用户，当我询问"宁德时代研报"时，Agent 应该能正确提取雪球搜索页面的内容，而不是报告"未能成功提取内容"。

### BUG-08：意图分类器规则优先级错误（P1）

**现象**：
- 用户输入"搜索东方财富的贵州茅台新闻"
- 被分类为 `news.search`（置信度 0.8），而非 `web.browse`（置信度 0.85）
- 导致调用 `news.search` 工具（mock 数据）而非 `web.browse`（CDP 实时数据）
- 同时 `news.search` 参数提取返回空 `{}`

**根因**：
- `classifyIntentLocal` 遍历 `LOCAL_RULES` 数组，返回**首个匹配**的规则
- `news.search` 规则在数组中排在 `web.browse` 之前
- "搜索...东方财富...新闻" 同时匹配 `news.search` 规则（0.8）和 `web.browse` 规则（0.85）
- 由于先匹配到 `news.search`（0.8），更高置信度的 `web.browse`（0.85）被跳过

**修复**：将 `classifyIntentLocal` 改为遍历所有规则，返回**最高置信度**的匹配

**用户故事**：
> 作为用户，当我搜索"东方财富的贵州茅台新闻"时，Agent 应该打开东方财富网站进行实时搜索，而不是用本地 mock 数据。

---

### BUG-09：CDP 编码问题导致所有网站内容提取为空（P0）

**现象**：
- 百度、东方财富、新浪等多个网站，轮询检测到页面有内容（`textLength: 2817`），但最终提取结果始终为空（`textLength: 0`）
- 标题乱码：`瀹佸痉鏃朵唬鐮旀姤_鐧哄害鎼滅储` = "宁德时代研报_百度搜索"
- 即使用百度搜索（SSR 页面，不需要等 JS 渲染），提取结果仍为空

**根因**：
- CDP `Runtime.evaluate` 存在 UTF-8 编码问题，涉及中文的脚本表达式执行异常
- CDP 脚本报错时返回 `{ exceptionDetails }` 而非 `{ result }`，原代码 `result?.value || ''` 静默吞错
- `EXTRACTION_SCRIPT` 中的 `el.remove()` 破坏性删除 DOM 元素，可能误删搜索结果容器

**修复**：从 CDP `Runtime.evaluate` 重构为 Electron 原生 `webContents.executeJavaScript()`

**用户故事**：
> 作为用户，当我询问"宁德时代研报"时，Agent 应该能从搜索结果页提取到实际内容，而不是每次都报告"未能成功获取到具体内容"。

### BUG-10：新 Session 首次提问后未自动更新名称（P2）

**现象**：
- 开启应用后自动弹出的新 Session，提问后标题仍为"新对话"
- 后续创建的 Session 能正常自动命名

**根因**：
- `handleSend` 中 `createSession()` 更新了 zustand store，但 `useCallback` 闭包中的 `sessions` 是旧值
- `sessions.find((s) => s.id === sessionId)` 找不到刚创建的 session → `autoRenameSession` 不触发

**修复**：`createSession()` 后从 `useSessionStore.getState()` 获取最新 sessions

**用户故事**：
> 作为用户，当我新建对话并提问后，对话标题应该自动更新为我的问题摘要，而不是一直显示"新对话"。

---

### BUG-11：浏览器 toggle 关闭后重开设置页仍显示开启（P2）

**现象**：
- 在设置页关闭"启用浏览器自动化" toggle
- 关闭设置页再打开，toggle 显示为开启

**根因**：
- `BrowserSettings` 组件中 `enabled` 状态用 `useState(true)` 管理，未持久化
- 组件卸载（关闭设置页）后状态丢失，重新挂载时重置为 `true`

**修复**：将 `browserEnabled` 状态迁移到 `usePreferenceStore`，随 persist 持久化到 localStorage

**用户故事**：
> 作为用户，当我关闭浏览器自动化后，关闭设置页再打开，应该仍然显示为关闭状态。

---

### BUG-12：用户指定东方财富但 fallback 用了百度（P1）

**现象**：
- 用户输入"用东方财富查询查询贵州茅台的实时行情..."
- `extractToolArgs` 返回空 `{}`，触发 fallback
- fallback 硬编码 `domain: 'baidu.com'`，忽略了用户指定的"东方财富"
- 搜索 query 也未清理"用东方财富查询"前缀，整句丢给百度搜索

**根因**：
- `extractFallbackBrowseQuery` 未从 query 中移除网站名称
- fallback 逻辑硬编码 `baidu.com`，未从用户输入检测域名

**修复**：
1. 新增 `detectDomainFromInput()` 函数，从用户输入中检测"东方财富"等关键词 → 返回 `eastmoney.com`
2. 改进 `extractFallbackBrowseQuery()`，移除网站名称前缀
3. LLM 返回 query 但无 domain 时，也用 `detectDomainFromInput` 补充

**用户故事**：
> 作为用户，当我说"用东方财富查询茅台行情"时，Agent 应该打开东方财富网站搜索，而不是百度。

### BUG-13：web.browse 规则未匹配口语化"搜"和"资讯"（P1）

**现象**：
- 用户输入"东方财富搜一下中际旭创最新资讯"
- 被分类为 `news.search`（0.8），而非 `web.browse`
- `news.search` 返回 mock 数据，无实际价值

**根因**：
- web.browse 第一组只匹配"搜索"不匹配"搜"（口语化缩写）
- web.browse 第二组没有"资讯"关键词
- 导致"搜一下...资讯"只匹配 `news.search` 规则

**修复**：
1. web.browse 第一组加"搜"
2. web.browse 第二组加"资讯"
3. 第二条规则（域名在前）也加"搜"

**用户故事**：
> 作为用户，当我说"东方财富搜一下中际旭创最新资讯"时，Agent 应该打开东方财富网站搜索，而不是返回 mock 数据。

### BUG-14：合并 news.search → web.browse（P1）

**背景**：
- `news.search` 工具基于 `mockNewsSearch()` 返回预设假数据，无实际价值
- `web.browse` 通过 CDP/executeJavaScript 实时抓取网页内容，可返回真实新闻
- 两个工具的功能高度重叠（都是"搜新闻"），用户无法区分

**决策**：`web.browse` 取代 `news.search`。将 `news.search` 意图的所有路由指向 `web.browse` 工具。

**需要同步修改的 UI**：
- 快捷功能"搜新闻"按钮 → 改用 `web.browse`
- 推荐问话"最近有什么新能源行业新闻" → intent 从 `news.search` 改为 `web.browse`

**用户故事**：
> 作为用户，当我点"搜新闻"快捷按钮时，Agent 应该打开真实网站搜索新闻，而不是返回假数据。

---

### BUG-15："我之前关注哪些公司"被误分类为 preference.update（P1）

**现象**：
- 用户输入"我之前关注哪些公司来着？"
- 被分类为 `preference.update`（0.75）→ 跳过工具调用，直接返回"请在界面中手动完成"
- 用户期望：Agent 通过向量记忆检索用户历史偏好并回答

**根因**：
- `preference.update` 规则 `/(风险偏好|风险|偏好|关注板块|关注|我喜欢|我不喜欢|记住|记住我)/` 匹配了"关注"
- "我之前**关注**哪些公司"是**查询**偏好，不是**更新**偏好
- `preference.update` 被跳过（UI 操作），不触发记忆检索

**修复**：`preference.update` 规则不应匹配"关注"的查询用法，只匹配明确的更新意图

**用户故事**：
> 作为用户，当我说"我之前关注哪些公司"时，Agent 应该检索记忆并回答，而不是让我"手动完成"。
