# AInvest Agent v4.1 PRD — 视觉体系深度优化

> 版本：v4.1.0
> 日期：2026-06-06
> 状态：需求评审中
> 依赖：v4.0.0 已发布

---

## 一、产品概述

v4.0.0 完成了三栏背景色微调（`panel-left`/`panel-center`/`panel-right`）和行情看板信息密度升级，但视觉体系仍停留在"素色块"阶段。v4.1 聚焦**视觉专业感与层次感的深度升级**，目标：让界面第一眼即具备金融科技平台的高级感，三栏不再是三个灰块，而是具备空间深度和信息层级的现代工作台。

---

## 二、版本目标

**"从灰块到空间——让投研工作台拥有 Bloomberg Terminal 的专业深度和 Linear 的现代精致"**

---

## 三、用户故事

### US-411：我想看到具备空间深度的界面
> 作为用户，当我打开应用时，我希望三栏不是三个相近的灰块，而是有微妙的明暗层次和玻璃态质感，让我一眼就能区分功能区域并感受到专业感。

### US-412：我想看到更精致的卡片和数据展示
> 作为用户，当我在行情看板浏览指数卡片、在聊天面板查看 Agent 回复时，我希望卡片有悬浮感和 hover 动效，而不是贴膏药式的实色填充。

### US-413：我想看到符合金融认知的配色
> 作为用户，当我看到涨跌数字时，我希望颜色饱和度和对比度足够让我快速判断方向；当我在深夜使用时，主色调不应刺眼，但又要保持专业辨识度。

## 四、三套配色方案对比

### 对比维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 专业感 | 高 | 是否符合金融/投研平台气质 |
| 现代感 | 高 | 是否具备 2024-2025 主流 SaaS 设计语言的精致度 |
| 可读性 | 高 | 深色背景上的文字/数字对比度是否充足 |
| 辨识度 | 中 | 三栏差异是否一目了然 |
| 实现成本 | 中 | 改动范围是否可控 |

### 方案 A：Professional Fintech（专业金融）

> 灵感来源：Bloomberg Terminal / TradingView Pro / 同花顺专业版

**设计哲学**：深色墨水底 + 高饱和金融色 + 等宽数字字体，传递"严肃交易工具"的气质。

#### 色值表

| Token | 色值 | 说明 |
|-------|------|------|
| `panel-left` | `#080d1a` | 深墨色，行情看板背景 |
| `panel-center` | `#0B1120` | 钴蓝黑，聊天面板基准 |
| `panel-right` | `#0e1526` | 石墨蓝，Session 列表 |
| `background` | `#030712` | 全局最底层背景（极少使用） |
| `surface` | `#111827` | 卡片背景 |
| `surface-elevated` | `#1a2236` | 悬浮/选中态卡片 |
| `surface-hover` | `#1e293b` | hover 态 |
| `border` | `#1e293b` | 主边框 |
| `border-subtle` | `#172033` | 极淡边框（玻璃态卡片） |
| `primary` | `#2563eb` | 钴蓝主色 |
| `primary-hover` | `#1d4ed8` | 主色 hover |
| `primary-glow` | `rgba(37,99,235,0.15)` | 主色发光效果 |
| `text` | `#f1f5f9` | 主文字（接近纯白） |
| `text-secondary` | `#94a3b8` | 次要文字 |
| `text-muted` | `#64748b` | 禁用/placeholder |
| `success` | `#10b981` | 青绿涨色 |
| `danger` | `#f43f5e` | 玫瑰红跌色 |
| `warning` | `#f59e0b` | 琥珀金预警 |

#### 视觉特征
- **三栏差异**：左栏最深（`#080d1a`），中栏基准（`#0B1120`），右栏最浅（`#0e1526`），色差 12-15%
- **卡片质感**：`bg-surface/80 backdrop-blur-md border border-border-subtle rounded-xl`，玻璃态悬浮感
- **数字字体**：所有价格、涨跌幅、指数点位强制使用 `font-mono`
- **主色发光**：按钮/激活态使用 `box-shadow: 0 0 20px primary-glow`
- **渐变底纹**：聊天面板输入框区域可使用极微弱的 `bg-gradient-to-t from-primary-glow to-transparent`

#### 优劣分析
| 优势 | 劣势 |
|------|------|
| 专业感极强，一眼金融 | 颜色偏冷，部分用户可能觉得"硬" |
| 三栏层次极其分明 | 玻璃态在低性能设备上可能掉帧 |
| 数字可读性最佳 | 改动范围较大（~8 个文件） |

### 方案 B：Midnight Minimal（午夜极简）

> 灵感来源：Linear / Vercel Dashboard / Raycast

**设计哲学**：统一深灰底 + 极细边框区分 + 克制的色彩，传递"工程师审美"的精致与冷静。

#### 色值表

| Token | 色值 | 说明 |
|-------|------|------|
| `panel-left` | `#0a0a0f` | 极深灰，接近纯黑 |
| `panel-center` | `#0c0c12` | 基准深灰 |
| `panel-right` | `#0f0f16` | 稍浅深灰 |
| `background` | `#050508` | 全局底层 |
| `surface` | `#13131a` | 卡片背景 |
| `surface-elevated` | `#1a1a22` | 悬浮态 |
| `surface-hover` | `#1e1e26` | hover 态 |
| `border` | `#1f1f28` | 主边框（极细） |
| `border-subtle` | `#1a1a22` | 几乎不可见的边框 |
| `primary` | `#6366f1` | 靛紫主色 |
| `primary-hover` | `#4f46e5` | 主色 hover |
| `text` | `#e2e8f0` | 主文字 |
| `text-secondary` | `#94a3b8` | 次要文字 |
| `text-muted` | `#64748b` | 禁用 |
| `success` | `#34d399` | 薄荷绿涨色 |
| `danger` | `#fb7185` | 浅玫瑰跌色 |
| `warning` | `#fbbf24` | 柔和琥珀 |

#### 视觉特征
- **三栏差异**：不靠颜色区分，而靠**边框**——左栏和中栏之间有 `border-r border-border`，中栏和右栏之间有 `border-l border-border`
- **卡片质感**：无边框或极细边框（`border-subtle`），靠微弱背景差（`surface` vs `panel-*`）区分层级
- **极少渐变**：几乎不使用渐变和发光效果，纯靠色阶和留白
- **圆角克制**：卡片圆角 `rounded-lg`（8px），不追求大圆角

#### 优劣分析
| 优势 | 劣势 |
|------|------|
| 极度精致、不喧宾夺主 | 三栏差异太小，可能一眼仍分不清 |
| 性能最优（无 backdrop-blur） | 金融感较弱，更像开发工具 |
| 改动范围最小 | 用户可能觉得"和之前差不多" |
| 长期维护成本最低 | 对"第一印象"提升有限 |

### 方案 C：Hybrid（混合推荐）

> 结合方案 A 的专业分层感和方案 B 的精致克制

**设计哲学**：用方案 A 的三栏渐变分层做骨架，用方案 B 的极简边框和克制动效做细节，主色保留金融钴蓝而非靛紫。

| `panel-center` | `#0B1120` | 方案 A（钴蓝黑） |

| `surface-hover` | `#1e293b` | 方案 A |
| `border` | `#1e293b` | 方案 A |
| `border-subtle` | `#172033` | 方案 A |
| `primary` | `#2563eb` | 方案 A（钴蓝） |
| `primary-hover` | `#1d4ed8` | 方案 A |
| `primary-glow` | `rgba(37,99,235,0.12)` | 方案 A（减淡） |
| `text` | `#f1f5f9` | 方案 A |
| `text-secondary` | `#94a3b8` | 共用 |
| `text-muted` | `#64748b` | 共用 |
| `success` | `#10b981` | 方案 A（青绿） |
| `danger` | `#f43f5e` | 方案 A（玫瑰红） |
| `warning` | `#f59e0b` | 方案 A（琥珀金） |

#### 视觉特征
- **三栏差异**：采用方案 A 的强分层（色差 12-15%），一眼可辨
- **卡片质感**：玻璃态但**克制**——`backdrop-blur-sm`（而非 md）+ `border-subtle` + `shadow-sm`
- **无边框优先**：能用背景差区分的就不加边框，必须加边框的用 `border-subtle`
- **动效克制**：hover 仅 `transition-colors duration-150` + `bg-surface-hover`，不追求抬升阴影
- **数字字体**：仅行情数据、代码块使用 `font-mono`，普通文本保持 `font-sans`
- **无全局渐变**：聊天面板不使用渐变底纹，仅在关键按钮/激活态使用微弱 glow

#### 优劣分析
| 优势 | 劣势 |
|------|------|
| 专业感 + 精致感兼顾 | 不是最惊艳的，是"最稳妥的" |
| 三栏层次分明但不突兀 | 需要更多设计决策（哪里克制、哪里突出） |
| 性能影响可控（blur-sm） | |
| 与现有 v4 代码兼容度最高 | |

## 六、PM 推荐

**推荐方案 C（Hybrid）**，理由：

1. **用户核心诉求是"第一印象好"**：方案 A 过强可能显得厚重，方案 B 过弱改善不明显，C 恰好处于甜点区
2. **v4 已具备骨架**：v4 的 `panel-*` 色值体系可直接平滑升级，无需推翻重建
3. **长期维护成本**：C 的克制设计不会随着时间显得过时，A 的强风格可能 1 年后显得老旧
4. **性能安全**：`blur-sm` 在绝大多数设备上无感知开销，`blur-md` 在低端 Windows 设备上可能掉帧

## 十、风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| Tailwind token 变更导致组件色彩断裂 | 中 | 全局搜索旧 token 名，确保无残留；Reviewer 做色彩一致性专项 |
| `backdrop-blur-sm` 在 Windows 低端设备掉帧 | 低 | 测试目标设备；如掉帧可降级为纯半透明 `bg-surface/90` |
| 三栏色差过强破坏一致性 | 低 | 色差控制在 12-15% 以内；用户审阅截图确认 |
| 颜色变更导致图表（recharts）主题不兼容 | 低 | StockChart / MarketDistributionChart 的 stroke/fill 使用独立色值，不受 token 变更影响 |

## 十二、决策记录

| 决策项 | 选择 | 原因 |
|--------|------|------|
| 配色方案 | 方案 C Hybrid | 兼顾专业感与精致感，与 v4 兼容度高 |
| 玻璃态强度 | `blur-sm` 而非 `blur-md` | 性能安全，Windows 设备友好 |
