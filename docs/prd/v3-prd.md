# AInvest Agent v3 PRD

> 版本：v3.0.0
> 日期：2026-06-06
> 状态：评审通过（技术评审已确认全部决策）

---

## 一、产品概述

AInvest Agent v3 在 v2 大模型驱动 Agent 的基础上，聚焦**可观测性**和**用户体验优化**。核心目标：让用户清楚看到 Agent 在做什么，降低使用门槛，提升交互效率。

---

## 二、版本目标

**让用户"看得见、用得顺、找得到"** —— Agent 运行过程可视化、快捷输入降低操作成本、空状态引导提升首次体验。

---

## 三、用户故事

### US-301：我想看到 Agent 在做什么
> 作为用户，当我发送消息后，我希望看到 Agent 正在执行哪些步骤（如识别意图、调用工具），这样我不会觉得应用卡死了。

### US-302：我想快速输入常用查询
> 作为用户，我希望在输入框附近有几个常用功能的快捷按钮，点击就能快速发起查询，不用每次都打字。

### US-303：我想知道新对话可以问什么
> 作为新用户，当我创建一个空白对话时，我希望看到一些推荐问题，引导我知道这个 Agent 能做什么。

### US-304：我想让 Session 有有意义的名称
> 作为用户，我希望新建的 Session 能自动根据我的第一条消息命名，这样我能在侧边栏快速找到想要的对话。

### US-305：我想在开发时调试 Agent
> 作为开发者/测试人员，我希望有一个面板能实时查看 Agent 的运行日志，方便定位问题。

## 四、功能列表

### 4.1 加载中 + Thinking 块展示（New Feature）

**功能描述**：
在 Agent 处理用户请求的整个过程中，在 Agent 回复消息区域上方展示一个可折叠的 Thinking 块，实时显示当前执行步骤。

**展示内容**：
1. `intent.recognizing` — "正在理解您的问题..."
2. `intent.resolved` — "已识别意图：[行情查询/新闻搜索/...]"
3. `tool.extracting` — "正在提取参数..."
4. `tool.calling` — "正在调用 [market.query]..."
5. `tool.result` — "已获取工具结果"
6. `llm.generating` — "正在生成回复..."
7. `llm.streaming` — "正在输出..."

**交互设计**：
- 默认状态：折叠（只显示一行 "Agent 正在思考..."）
- 点击展开：显示完整的步骤列表和时间线
- 步骤完成时：对应步骤打勾或高亮
- 整轮结束后：Thinking 块保持可查看状态（不自动消失）

**验收标准**：
- [ ] 用户发送消息后，Thinking 块在 200ms 内出现
- [ ] 每个步骤在对应事件触发后 100ms 内更新显示
- [ ] 默认折叠状态，点击可展开/收起
- [ ] 工具意图显示工具名称和参数摘要
- [ ] 非工具意图（如 general.chat）跳过工具相关步骤
- [ ] 步骤失败时显示错误状态（红色标记）

---

### 4.2 DevTool Agent 日志面板（New Feature）

**功能描述**：
为开发者/测试人员提供一个快捷键唤起的浮动面板，实时展示当前 Session 的 Agent 运行日志。

**入口**：
- 快捷键：`Ctrl+Shift+L`
- 面板形式：屏幕右侧滑出的浮动面板（宽度 480px），半透明背景

**展示内容**：
- 事件时间线（树形结构，按 turn 分组）
- 每个事件显示：时间戳、事件类型、关键数据摘要
- 支持点击展开查看完整数据（如完整的请求体、响应体）
- 支持按事件类型过滤（agent/intent/tool/llm/ui）
- 支持导出当前 Session 日志为 JSON

**事件类型覆盖**：
- `agent.turn.start/end`
- `agent.intent.resolved`
- `agent.tool.detected/args/result`
- `agent.llm.request/error`
- `agent.context.prepared`

**验收标准**：
- [ ] 快捷键 `Ctrl+Shift+L` 能正常唤起/关闭面板
- [ ] 面板展示当前 Session 的所有日志事件
- [ ] 支持按事件类型过滤
- [ ] 支持导出 JSON
- [ ] 新事件到达时自动滚动到底部
- [ ] 面板不影响正常交互（非模态）

### 4.3 自动总结 Session 名称（New Feature）

**功能描述**：
当用户在一个新 Session 中发送第一条消息后，自动根据消息内容生成 Session 名称。

**方案**：本地规则（不调用 LLM）
- 取用户第一条消息的前 10 个汉字/字符
- 如果第一条消息是英文，取前 15 个字符
- 去除首尾空格和标点
- 如果截取后为空，使用默认名称"新对话"

**触发时机**：
- 用户发送第一条用户消息（role=user）后
- 仅触发一次，后续消息不再更新名称

**覆盖策略**：
- 自动命名仅在没有手动重命名时生效
- 用户手动重命名后，标记为 `isCustomNamed: true`，不再自动更新

**验收标准**：
- [ ] 发送第一条消息后，Session 名称自动更新
- [ ] 名称为消息前 10 个汉字（中文）或前 15 个字符（英文）
- [ ] 用户手动重命名后，不再自动更新
- [ ] 空消息或纯标点时，使用默认名称"新对话"

### 4.4 快捷工具按钮（New Feature）

**功能描述**：
在聊天输入框上方展示 4 个固定快捷工具按钮，用户点击后快速填充对应提示词到输入框。

**按钮列表**：
| 按钮 | 填充文本 |
|------|---------|
| 查行情 | "查一下 [股票代码] 的行情" |
| 搜新闻 | "搜一下 [关键词] 的新闻" |
| 看档案 | "看看 [股票代码] 的公司档案" |
| 做回测 | "对 [股票代码] 做 [策略名] 回测" |

**交互设计**：
- 位置：输入框上方，横向排列
- 样式：小尺寸 pill 按钮（圆角标签样式）
- 点击行为：填充到输入框，不直接发送（用户可修改后发送）
- 占位符：`[股票代码]`、`[关键词]`、`[策略名]` 光标自动定位到第一个占位符

**验收标准**：
- [ ] 4 个按钮正常展示在输入框上方
- [ ] 点击后对应文本填充到输入框
- [ ] 占位符 `[xxx]` 被选中或光标定位到第一个占位符
- [ ] 用户可修改填充内容后再发送
- [ ] 不影响现有输入框的 Enter 发送逻辑

### 4.5 Prompt 统一收口（Optimization）

**功能描述**：
将所有散落在业务代码中的 inline prompt 统一迁移到 `src/renderer/services/agent/prompts.ts`，实现单一数据源。

**迁移范围**：
- `intentClassifier.ts:70` 中的意图识别 inline prompt → `prompts.ts`
- `agentEngine.ts:108-117` 中的工具参数提取 `promptMap` → `prompts.ts`

**不改内容，只改位置**。

**验收标准**：
- [ ] 所有 prompt 定义集中在 `prompts.ts`
- [ ] `intentClassifier.ts` 和 `agentEngine.ts` 只引用，不定义 prompt
- [ ] 功能无 regression（评测集通过率不变）

**Prompt 优化流程规定**：
- 任何 prompt 内容变更前，必须先跑 `run-intent-eval.ts` 记录基线
- 变更后再次跑评测集，通过率下降 > 5% 时阻断合并
- 优化流程与大版本迭代解耦，可在任意小版本中执行

### 4.6 LLM 意图分类评测升级（Optimization）

**功能描述**：
新增 LLM 层意图分类评测脚本，调用真实 LLM API 验证意图识别准确率。

**新脚本**：`test/eval/run-intent-llm-eval.ts`
- 读取 `intent-eval.json`
- 对每个用例调用 `classifyIntentLLM`（真实 API）
- 输出准确率报告（同 `run-intent-eval.ts` 格式）
- 与正则层评测对比

**触发频率**：
- 每日定时（CI 定时任务）
- Prompt 变更时
- 模型配置变更时

**验收标准**：
- [ ] 新脚本可正常运行
- [ ] 输出包含：总准确率、各意图准确率、失败 case 明细
- [ ] 与正则层评测结果可对比
- [ ] 支持 `--model` 参数切换模型

**展示时机**：
- Session 为空（0 条消息）时

- 样式：卡片式按钮，2x2 网格布局
- 每个卡片包含：问题文字 + 对应意图类型的图标

**交互**：
- 点击卡片直接发送该问题（无需用户再确认）
- 发送后卡片消失，显示正常的消息列表

**验收标准**：
- [ ] 空 Session 时展示推荐卡片
- [ ] 4 个问题正确展示
- [ ] 点击后直接发送

## 五、交互流程

### 5.1 首次使用引导流程

```
打开应用
  ↓
展示空 Session（自动创建"新对话"）
  ↓
消息列表中央展示推荐问题卡片（4个）
  ↓
用户点击卡片 / 手动输入消息
  ↓
Session 名称自动更新（取第一条消息前10字）
  ↓
Thinking 块出现 → 流式展示步骤 → Agent 回复
```

### 5.2 快捷工具使用流程

```
用户在输入框上方看到 4 个快捷按钮
  ↓
点击"查行情"
  ↓
输入框填充："查一下 [股票代码] 的行情"
  ↓
光标定位到 [股票代码]
  ↓
用户输入"600519"，替换占位符
  ↓
按 Enter 发送
  ↓
Thinking 块展示步骤 → Agent 回复行情数据
```

### 5.3 开发者调试流程

```
开发者运行应用，进行对话测试
  ↓
发现 Agent 行为异常
  ↓
按 Ctrl+Shift+L 唤起 DevTool 面板
  ↓
查看当前 Session 的事件时间线
  ↓
定位到异常事件，展开查看完整数据
  ↓
导出日志 JSON，提交 issue
```

## 七、验收标准

### 7.1 功能验收

| 功能 | 验收标准 | 优先级 |
|------|---------|--------|
| Thinking 块 | 步骤实时更新、默认折叠、可展开、工具意图显示工具名 | P0 |

- Thinking 块出现延迟 < 200ms

- DevTool 面板唤起延迟 < 100ms
- 自动命名处理延迟 < 50ms（本地规则）

### 7.3 质量验收

- 意图识别评测集通过率无 regression（维持 ≥ 94.3%）
- E2E 评测集通过率无 regression（维持 ≥ 86.7%）

## 十二、附录

| Prompt 优化 | 暂不优化内容 | 与大版本迭代解耦 |
| 背景优化 | 等设计三版方案 | 需要专业设计输入 |
| 头像 | 用户找设计 | 品牌一致性要求 |
