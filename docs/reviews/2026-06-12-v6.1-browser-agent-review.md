### 文件：`src/main/services/browserCDP.ts`

#### [BLOCKER-1] clickElement nodeId → 元素定位逻辑完全错误
- **位置**：第 395-398 行
- **问题**：`const targetIndex = parseInt(nodeId, 10) % elementInfo.length` — AXTree 的 nodeId 不是序号索引，而是 CDP 内部分配的字符串 ID（如 "446"、"552"）。用 `parseInt` 取模来匹配 DOM 元素是完全错误的，会导致**随机点击错误元素**。
- **POC 验证也证明了这一点**：百度搜索页 AXTree 返回的 nodeId 有 "446"、"458"、"549" 等，而 DOM 中的交互元素数量远小于这些数字。
- **建议**：改用**文本匹配**策略 — LLM 决策给出 nodeId 后，在 AXTree 中找到该 nodeId 对应的 `name` 和 `role`，然后在 DOM 中用 JS 查找文本匹配的元素获取坐标。
```typescript
// 正确方案：
// 1. 从 AXTree 中找到 nodeId 对应的 name/role
// 2. 在 DOM 中用 JS 查找文本匹配的可交互元素
// 3. 获取 getBoundingClientRect 坐标
// 4. CDP 点击
```
- **影响**：智能操作模式下点击操作几乎必定定位到错误元素，功能完全不可用。

#### [BLOCKER-2] typeText 忽略了 nodeId 参数，永远聚焦第一个 input
- **位置**：第 451-468 行
- **问题**：`typeText` 方法中 `nodeId` 参数未被使用，代码始终查找第一个 input 元素并聚焦。如果页面有多个 input（搜索框 + 登录框等），会错误地在登录框输入搜索关键词。
- **建议**：同 BLOCKER-1，用 nodeId 在 AXTree 中找到元素 name/role，然后在 DOM 中文本匹配定位。
- **影响**：多输入框页面上输入操作会定位到错误元素。

#### [WARNING-1] CDP attach 失败后降级逻辑有 bug
- **位置**：agentEngine.ts 第 437-438 行
- **问题**：`const text = await window.browser.open({ url: '__current__' })` — 传入 `__current__` 作为 URL，但 `browser:open` IPC 会调用 `browserService.browse({ url: '__current__' })`，URL 校验会失败（不是合法 URL），降级逻辑永远不会工作。
- **建议**：降级时应直接用 `browseResult.text`（browse 已经成功了，文本已拿到）。
```typescript
// 修复：
if (!cdpAttached) {
  await window.browser.close()
  return `已访问 ${browseResult.title}\n\n提取内容：\n${browseResult.text}`
}
```
- **影响**：CDP attach 失败时降级不生效，用户看到错误信息。

#### [WARNING-2] clickElement 在 CDP 未 attach 时静默成功但不点击
- **位置**：第 404-420 行
- **问题**：如果 `this.cdpAttached === false`，方法跳过 CDP 点击但返回 `{ success: true }`。调用方以为点击成功了，实际什么都没发生。
- **建议**：非 CDP 模式下应使用 `executeJavaScript` 的 `a.click()` 作为 fallback（POC 验证了可行），或返回 `{ success: false, error: 'CDP not attached' }`。
- **影响**：边缘情况下点击操作静默失败。

#### [WARNING-3] getAXTree 中 AXTree 节点的类型断言过于宽松
- **位置**：第 324-333 行
- **问题**：大量使用 `as Record<string, string>` 和 `as Record<string, unknown>` 类型断言，绕过了类型检查。CDP `Accessibility.getFullAXTree` 返回的节点结构是确定的，应该定义接口代替断言。
- **建议**：定义 CDP AXTree 原始节点接口（可以放在 types 里），用类型声明代替 `as` 断言。
- **影响**：可维护性差，如果 CDP 返回结构变化会导致运行时错误。

#### [SUGGESTION-1] SEARCH_URL_TEMPLATES 重复定义
- **位置**：agentEngine.ts 第 624-634 行
- **问题**：`SEARCH_URL_TEMPLATES` 在 `src/renderer/services/tools/browser.ts` 中已有定义，agentEngine.ts 又内联了一份。违反 DRY 原则。
- **建议**：将 `buildSearchUrl` 和 `SEARCH_URL_TEMPLATES` 从 `browser.ts` 导出，在 agentEngine.ts 中直接 import。
- **影响**：如果模板变更需要改两处，容易遗漏。

### 文件：`src/renderer/services/agent/agentEngine.ts`

#### [BLOCKER-3] BROWSER_ACTION_PROMPT 存在 Prompt 注入风险
- **位置**：prompts.ts 第 113-144 行，agentEngine.ts 第 662-667 行
- **问题**：用户输入 `userInput` 直接通过 `.replace('{userInput}', userInput)` 插入到 system prompt 中。如果用户输入包含 `{url}`、`{title}` 等占位符或 JSON 格式文本，可能导致 prompt 结构被破坏或 LLM 被误导。
- **建议**：对用户输入进行转义（替换 `{` 和 `}` 为其他字符），或改用模板字符串而非 replace。
```typescript
// 修复方案：
const safeUserInput = userInput.replace(/[{}]/g, '')
const prompt = BROWSER_ACTION_PROMPT
  .replace('{userInput}', safeUserInput)
  // ...
```
- **影响**：恶意/特殊用户输入可能破坏 Agent Loop 的 LLM 决策。

#### [WARNING-4] `window.browser.extractCurrentPageText` 使用可选链调用
- **位置**：第 452、478、491、498、585 行
- **问题**：`window.browser.extractCurrentPageText?.()` — 但 `BrowserAPI` 接口中 `extractCurrentPageText` 不是可选属性，不需要 `?.`。这里用 `?.` 是因为该方法在 Preload 中没有暴露。
- **实际验证**：检查 preload — `extractCurrentPageText` 确实**没有在 BrowserAPI 接口和 preload 中注册**！这个方法只存在于主进程 `browserCDP.ts` 中，渲染进程调用 `window.browser.extractCurrentPageText` 会返回 `undefined`。
- **影响**：Agent Loop 中所有 `extractCurrentPageText` 调用都会静默返回 `undefined`，降级为 `browseResult.text`（初始页面文本），无法提取点击后的新页面内容。**这是功能性问题**。
- **建议**：
  1. 在 `BrowserAPI` 接口中新增 `extractCurrentPageText`
  2. 在 preload 中注册 `browser:extractCurrentPageText` IPC
  3. 在 `ipcHandlers/browser.ts` 中新增对应 handler
  4. 去掉 `?.` 改为直接调用

#### [WARNING-5] 安全检查 isActionSafe 中 `target` 未找到时返回 false
- **位置**：第 379-380 行
- **问题**：`if (!target) return false` — 如果 AXTree 中找不到 nodeId 对应的节点（可能是因为简化过滤被截断了），操作被阻止。但这可能不是安全问题，而是 AXTree 截断导致找不到。
- **建议**：区分"找不到节点"和"确认是危险元素"两种情况。找不到节点应返回 true（允许尝试，clickElement 内部会处理），只有确认是危险元素才返回 false。
```typescript
if (!target) return true  // 找不到不阻止，让 clickElement 自己处理
```
- **影响**：部分合法点击操作可能被误拦截。

#### [WARNING-6] Agent Loop 中 onToolCall/onToolResult 回调不一致
- **位置**：第 146-171 行
- **问题**：agent 模式分支中，`onToolCall` 和 `onToolResult` 未被调用（extract 模式中调用了）。下游组件（如 BrowserToolCard）可能依赖这些回调来更新 UI。
- **建议**：在 agent 模式分支中也调用 `onToolCall('web.browse', args)`。
- **影响**：智能操作模式下 BrowserToolCard 可能不显示。

- **位置**：第 75-90 行

### 文件：`src/renderer/services/agent/prompts.ts`

#### [SUGGESTION-3] BROWSER_ACTION_PROMPT 缺少对 extract 后 LLM 回复的指导
- **位置**：第 113-144 行
- **问题**：Prompt 告诉 LLM 可以选 `extract` 结束，但没有说明 extract 后 Agent 会对提取的内容再做一次 LLM 总结。LLM 可能倾向于选 `done` 直接结束（不提取页面内容）。
- **建议**：在规则中增加："如果页面包含有用的详细信息，优先选择 extract 而非 done。extract 会提取完整页面内容用于后续总结。"
- **影响**：LLM 可能选错结束方式。
