## 详细审查

### [BLOCKER-1] `BrowserSettings.tsx` 白名单增删完全无效

- 位置：`src/renderer/features/settings/BrowserSettings.tsx` 第 13、29、35 行
- 问题：白名单修改仅保存在组件 `useState` 中，不持久化、不影响运行时。`BROWSER_DOMAIN_WHITELIST` 是编译时常量，`browserCDP.ts` 和 `browser.ts` 直接引用此常量做校验。用户在 UI 中添加/删除域名后刷新即丢失，且实际浏览时不生效。
- 建议：v6.0.1 中先禁用白名单增删功能（只保留 toggle），v6.1 再实现持久化白名单。
- 影响：用户添加域名后实际浏览仍被拒绝，属于功能缺陷。

### [BLOCKER-2] `constants/index.ts` TOOL_DEFINITIONS 与实际不同步

- 位置：`src/shared/constants/index.ts` 第 130-148 行
- 问题：`TOOL_DEFINITIONS` 中 `browser.open` 参数只有 `url` + `action`，缺少 `query` + `domain`。实际 `browser.ts` 中的 `BROWSER_TOOL_DEFINITION` 和 `executeBrowserTool` 已支持 `query`/`domain`。
- 建议：同步更新 `TOOL_DEFINITIONS`，或直接删除 `TOOL_DEFINITIONS`（如果无消费者）。
- 影响：如果其他代码引用了 `TOOL_DEFINITIONS` 来校验参数，会错误拒绝 `query`/`domain`。

### [WARNING-1] screenshot 模式失败时窗口未关闭

- 位置：`src/renderer/services/tools/browser.ts` 第 126-128 行
- 问题：`screenshot` 调用失败时直接 return，未调用 `window.browser.close()`，导致 BrowserWindow 泄漏。
- 建议：在 screenshot 失败分支也调用 `await window.browser.close()`。

### [WARNING-2] Mock 回复打字机效果 interval 未清理

- 位置：`src/renderer/features/chat/ChatPanel.tsx` 第 101-110 行
- 问题：`isConfigValid` 为 false 时用 `setInterval` 模拟打字，组件卸载后 interval 继续运行。
- 建议：用 `useEffect` 清理或 useRef 标记已卸载。

### [WARNING-3] news.search 残留在 INTENT_TYPES 中

- 位置：`src/shared/constants/index.ts` 第 40 行
- 问题：`INTENT_TYPES` 仍包含 `'news.search'`，LLM 返回此意图时通过校验但 `hasTool` 返回 false。
- 建议：从 `INTENT_TYPES` 中移除 `'news.search'`。

### [WARNING-4] LLM fetch 无超时控制

- 位置：`intentClassifier.ts` 第 240 行、`agentEngine.ts` 第 264 行
- 问题：`fetch` 调用无 `AbortController`，API 响应慢时无限等待。
- 建议：v6.1 统一添加超时。

### [WARNING-5] JSON.parse 无独立 try-catch

- 位置：`intentClassifier.ts` 第 267 行、`agentEngine.ts` 第 290 行
- 问题：LLM 返回格式错误的 JSON 时 `JSON.parse` 抛异常被外层 catch 吞掉，无日志。
- 建议：加独立 try-catch + `logWarn`。

### [SUGGESTION-1] BrowserCDPService 类名/文件名应更新

- 文件名 `browserCDP.ts` 和类名 `BrowserCDPService` 已不再使用 CDP，应改为 `BrowserService`。

### [SUGGESTION-2] PROMPT_VERSION 应更新

- `prompts.ts` 第 8 行 `PROMPT_VERSION = 'v6.0.0'` 应改为 `'v6.0.1'`。

### [SUGGESTION-3] validateConfig 应自动触发

- `usePreferenceStore.ts` 中 `setLLMConfig` 后 `isConfigValid` 不自动更新，需手动调 `validateConfig()`。

### [SUGGESTION-4] clearTurn 双重调用

- `agentEngine.ts` 的 `onDone` 和 `ChatPanel.tsx` 的 `onDone` 都调用 `clearTurn()`，幂等但冗余。
