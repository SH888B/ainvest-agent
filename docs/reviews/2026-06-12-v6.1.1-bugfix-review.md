## 详细审查

### BLOCKER-1: `runBrowserAgentLoop` 错误路径返回 string 而非对象

- 位置：`src/renderer/services/agent/agentEngine.ts` 第 500 行
- 问题：函数签名已改为 `Promise<{ text: string; sourceUrl: string; sourceTitle: string }>`，但 browse 失败时仍返回纯字符串 `return \`浏览失败：...\``
- 影响：TypeScript 编译可能通过（隐式 any），但运行时 `agentResult.text` 为 undefined，导致后续 `onSourceUrl(agentResult.sourceUrl, ...)` 报错或来源信息丢失
- 建议：改为 `return { text: \`浏览失败：...\`, sourceUrl: '', sourceTitle: '' }`

### BLOCKER-2: `app:openExternal` 无协议白名单

- 位置：`src/main/index.ts` 第 97-103 行
- 问题：`shell.openExternal(url)` 接受任意协议 URL，包括 `file://`、`javascript:`、`vbscript:` 等。恶意网页通过 AXTree 注入 `javascript:alert(1)` 作为链接，点击后会在系统浏览器执行脚本
- 影响：XSS / 代码注入风险
- 建议：增加协议白名单校验，只允许 `http://` 和 `https://`

### WARNING-1: `openExternal` 重复暴露

- 位置：`src/preload/index.ts` 第 108 行和第 116 行
- 问题：`openExternal` 同时存在于 `browserAPI` 对象内和单独通过 `contextBridge.exposeInMainWorld('openExternal', ...)` 暴露。两处功能完全相同，增加维护负担和攻击面
- 建议：移除第 116 行的单独暴露，统一使用 `window.browser.openExternal()`。同时移除 `Window` 接口中的 `openExternal` 声明

### WARNING-2: `extractFallbackBrowseQuery` 中的 `搜[一一下]*索?` 正则可能误匹配

- 位置：`src/renderer/services/agent/agentEngine.ts` 约 670 行
- 问题：`/搜[一一下]*索?/g` 会匹配"搜索"中的"搜"和"索"两个位置，导致"搜索"被替换两次（虽然结果正确）。但更重要的是，它也会匹配"索"这个单字（如"索引"中的"索"），把合法词误删
- 建议：改为更精确的 `/搜索?/g`（匹配"搜"或"搜索"），或 `/搜[一一下]*/g`（不匹配"索"）

### WARNING-3: `browse()` 后 `setWindowOpenHandler` 可能被页面导航重置

- 位置：`src/main/services/browserCDP.ts` 第 164-166 行
- 问题：`setWindowOpenHandler` 只在 `browse()` 创建窗口时设置一次。如果 Agent Loop 的 click 操作导致页面导航（`will-navigate`），新页面加载后 `setWindowOpenHandler` 仍然有效（它在 webContents 级别设置，不随导航重置）。但 `offscreen: true` 的窗口在导航后可能行为不同
- 影响：低风险，但建议在 Agent Loop 的每次 click 后验证 handler 仍然生效

### WARNING-4: LLM 决策 `max_tokens: 2000` 过大

- 位置：`src/renderer/services/agent/agentEngine.ts` 第 822 行
- 问题：GLM-5.1 是推理模型，`max_tokens: 2000` 意味着每次决策最多消耗 2000 token。5 步循环 = 最多 10000 token，加上 AXTree prompt 本身，单次 Agent Loop 可能消耗 15000+ token
- 建议：考虑改为 1000，并在日志中监控实际 completion_tokens 使用量。若推理模型输出 `reasoning_content`，实际消耗可能远大于表面值

### WARNING-5: `onSourceUrl` 在 extract 模式下获取 URL 的方式不稳定

- 位置：`src/renderer/services/agent/agentEngine.ts` 约 190 行
- 问题：extract 模式下从 `toolResultText` 正则匹配页面标题：`toolResultText.match(/已访问\s+(.+?)[\n\r]/)?.[1]`。这个正则依赖返回文本格式，如果格式变化就匹配不到
- 建议：改为从 `buildFinalUrl(args)` 获取 URL（agent 模式已经这样做了），extract 模式也应该如此

### SUGGESTION-1: AXTree 文本格式从 `[nodeId] role: "name"` 改为 `nodeId|role|name` 缺少文档

- 位置：`src/renderer/services/agent/prompts.ts`
- 问题：Prompt 中的 `{axTree}` 占位符没有说明格式，LLM 需要自行推断 `nodeId|role|name` 的含义
- 建议：在 BROWSER_ACTION_PROMPT 中加一行格式说明：`格式：nodeId|角色|名称`

### SUGGESTION-2: `MarkdownRenderer` 中 `<a>` 点击触发 `openExternal`

- 位置：`src/renderer/features/chat/components/MarkdownRenderer.tsx` 第 42-52 行
- 问题：LLM 回复中的 URL 链接现在点击会调用 `window.browser.openExternal()` 用系统浏览器打开。这可能不是用户预期——LLM 回复中常有参考链接，用户可能只是想选中文字，误触就弹浏览器
- 建议：考虑只在 `<a>` 上 `e.preventDefault()` 不做任何事，来源导航只通过气泡下方的专用按钮
