## 一、总体策略

### 1.1 开发策略

v4.1 为纯视觉优化，无业务逻辑变更，无新增依赖。采用 **Phase 串行 + Module 内串行** 策略：

```
Phase 1 基础层（Tailwind + 全局样式）
    ↓ [Reviewer 审核]
Phase 2 组件层（玻璃态改造 + 字体规范化）
    ↓ [Reviewer 审核 + 回归测试]
v4.1.0 发布
```

### 1.2 人员分工

| 角色 | 职责 | 介入时机 |
|------|------|---------|
| **Developer** | 按 Module 实现代码，自测通过后提交 Review | 每个 Module 开始时 |
| **Reviewer** | 执行 Code Review，输出 Review 报告 | Developer 提交后 |
| **Team Lead** | 确认发布流程（版本号 / CHANGELOG / tag） | Phase 2 结束后 |

## 二、Phase 划分与依赖关系

### Phase 1：基础层

**目标**：完成 Tailwind token 重构和全局样式层，为上层组件提供新色值体系。

| Module | 说明 | 依赖 | 预估工时 |
|--------|------|------|---------|
| M1.1 Tailwind token 重构 | `tailwind.config.js` colors 对象重构（15 变更 + 3 新增）；图表硬编码色值同步 | 无 | 1h |
| M1.2 全局样式层 | `index.css` 新增 `@layer base`：滚动条、selection、基础 transition | M1.1 | 0.5h |
| M1.3 MainLayout 适配 | 确认三栏背景类名与新 token 对齐；边框微调 | M1.1 | 0.5h |

**串行顺序**：M1.1 → M1.2 → M1.3
- M1.1 优先：token 是后续所有变更的基础
- M1.2 次之：依赖新 token 已定义
- M1.3 最后：纯确认性修改

**验收标准**：
- [ ] `npm run build` 零报错
- [ ] `npm run lint` 零错误
- [ ] 全局搜索旧色值（`#0f1117`、`#1a1d27`、`#2a2e3b`、`#3b82f6`）无残留
- [ ] 三栏背景色肉眼可辨差异

## 三、审核流程（Reviewer）

### 3.1 触发条件

Reviewer 在以下时机被调用：
1. Developer 完成 Phase 1 并自测通过
2. Developer 完成 Phase 2 并自测通过

### 3.2 审核步骤

```
Developer 提交 Review 请求
    ↓
Reviewer 执行：
  1. 读取 PRD 对应章节，确认需求覆盖度
  2. 读取技术架构文档，确认技术规范符合度
  3. 逐文件审查变更（git diff）
  4. 运行 TypeScript 编译检查
  5. 运行 ESLint 检查
  6. 全局搜索旧色值，确认无残留
    ↓
Reviewer 输出 Review 报告（docs/reviews/）
  - [BLOCKER] 必须修复
  - [WARNING] 建议修复
  - [SUGGESTION] 可选优化
    ↓
Developer 修复所有 [BLOCKER]
    ↓
Reviewer 确认修复，标记 "Review 通过"
```

### 3.3 审核重点

| Phase | Reviewer 重点 |
|-------|--------------|
| Phase 1 | 1. `tailwind.config.js` 新 token 与 PRD 色值表完全一致<br>2. 旧 token 全局无残留（搜索 `#0f1117`、`#1a1d27`、`#2a2e3b`、`#3b82f6`、`#e2e8f0`）<br>3. `index.css` `@layer base` 语法正确，不覆盖 Tailwind utilities<br>4. 图表硬编码色值已同步更新 |
| Phase 2 | 1. 玻璃态类名组合符合技术文档规范（`bg-surface/80 backdrop-blur-sm border border-border-subtle`）<br>2. hover 过渡使用 `transition-all duration-150`<br>3. 等宽字体仅用于数字/代码，普通文本保持 `font-sans`<br>4. 无 `backdrop-blur-md` / `backdrop-blur-lg` 误用<br>5. 滚动条样式不破坏现有布局 |

## 四、测试流程

### 4.1 三级测试

| 级别 | 执行者 | 时机 | 内容 |
|------|--------|------|------|
| **单元自测** | Developer | 每个 Module 完成后 | TS 编译 + ESLint + 功能自测（按验收标准逐项勾选） |
| **回归测试** | Reviewer | 每个 Phase 结束后 | v4 核心功能走查（Thinking / 快捷工具 / 自动命名 / DevTool / Markdown / 行情看板） |
| **集成验收** | Team Lead | 全部 Phase 完成后 | 完整视觉走查 + 性能指标验证 + 发布流程检查 |

### 4.2 回归测试基线

| 指标 | 基线值 | 允许波动 |
|------|--------|---------|
| TypeScript 编译 | 零报错 | 不允许警告 |
| ESLint | 零错误 | 警告需评估 |
| v4 功能回归 | 100% 通过 | Thinking / 快捷工具 / 自动命名 / DevTool / Markdown / 行情看板 |
| 意图识别评测 | ≥ 94.3% | 下降 > 5% 阻断合并 |
| E2E 评测 | ≥ 86.7% | 下降 > 5% 阻断合并 |

### 4.3 性能验收

| 指标 | 阈值 | 验证方式 |
|------|------|---------|
| 首次渲染 | 无白屏/闪烁 | 启动观察 |
| 消息列表滚动 | 无掉帧 | 滚动长列表 |
| 行情看板滚动 | 无掉帧 | 滚动总览页 |
| hover 响应 | < 16ms | 肉眼无感知延迟 |
