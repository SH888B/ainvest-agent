## 一、版本变更概要

v6 包含两个核心改动，测试重点围绕这两块展开：

| 变更域 | 内容 | 优先级 |
|--------|------|--------|
| Bug 修复 | Session 创建竞态、流式输出冻结、多轮消息丢失 | P0 |
| 浏览器自动化 | CDP 网页内容提取、截图、白名单安全 | P1 |

**测试策略**：P0 Bug 修复场景必须 100% 通过；P1 浏览器功能在白名单域名可用即可，反爬虫导致的提取失败不计为 Bug。

## 四、详细测试步骤

### TC-01：Session 创建防竞态（P0）

**目标**：验证快速点击"新建 Session"按钮不会批量创建多个 Session。

**对应 PRD**：US-601 / TC-01（连续点击 10 次只创建 1 个）

#### 步骤 1.1：记录当前 Session 数量

1. 观察左侧 Session 列表，记下当前 Session 数量：______

#### 步骤 1.2：快速连击测试

1. 快速连续点击 **10 次** "新建 Session"（➕）按钮
2. 观察：
   - 按钮在点击后是否有 loading 旋转图标
   - Session 列表是否只新增了 **1 个** Session

**预期结果**：
- [ ] 按钮点击后立即出现 loading 旋转图标（`Loader2` 动画）
- [ ] Session 列表只新增 **1 个** Session（不出现 2 个以上）
- [ ] 新 Session 自动成为当前活跃 Session
- [ ] 从点击到 Session 出现在列表中 < 200ms（视觉感知即时）

**通过标准**：10 次连击只创建 1 个 Session ✅

#### 步骤 1.3：loading 态验证

1. 点击"新建 Session"按钮一次
2. 在 loading 态消失前再次点击

**预期结果**：
- [ ] loading 期间按钮显示旋转图标，**不可再次点击**（`disabled` 状态）
- [ ] 不会创建重复 Session

**通过标准**：loading 态正确阻止重复创建 ✅

**⚠️ 失败排查**：
- 如果创建了多个 Session：`useSessionStore` 的 `isCreating` 防竞态未生效，检查 store 代码
- 如果按钮无 loading 图标：`SessionSidebar` 的 `disabled` 属性未生效

### TC-02：流式输出不冻结（P0）

**目标**：验证流式输出完成后界面正常渲染，不需要切换 Session 才能刷新。

**对应 PRD**：US-602 / TC-02（流式输出完成后 500ms 内界面正常）

#### 步骤 2.1：单次流式输出

1. 选择一个 Session
2. 发送：`你好，请简单介绍一下自己`
3. 观察 Agent 流式输出过程

**预期结果**：
- [ ] 文字逐字/逐段出现（流式效果）
- [ ] 流式输出**完成后**，界面自动显示完整内容
- [ ] **不需要**切换 Session 再切回来
- [ ] 500ms 内内容渲染完毕（视觉感知无延迟）

**通过标准**：流式结束后界面立即显示完整内容 ✅

#### 步骤 2.2：连续流式输出

1. 在同一 Session 中，连续发送 3 条消息：
   ```
   你好
   介绍一下贵州茅台
   新能源板块怎么样
   ```
2. 每条消息都等待流式输出完成后再发送下一条

**预期结果**：
- [ ] 每条消息的流式输出完成后，界面都能正常显示
- [ ] 不需要任何手动操作来"刷新"界面

**通过标准**：连续 3 次流式输出均无冻结 ✅

**⚠️ 失败排查**：
- 如果流式结束后界面卡住不动：`MessageList` 的 zustand 订阅可能仍有问题，检查 `useChatStore` selector
- 如果切换 Session 再切回才显示：`useMemo` 订阅模式未完全移除

### TC-03：多轮对话消息不丢失（P0）

**目标**：验证连续多轮对话后消息即时显示，且持久化正常。

**对应 PRD**：US-603 / TC-03, TC-04

#### 步骤 3.1：连续发送消息

1. 选择一个 Session
2. 快速连续发送 5 条消息（不等 Agent 回复完就发下一条）：
   ```
   1+1等于几
   2+2等于几
   3+3等于几
   4+4等于几
   5+5等于几
   ```
3. 观察：
   - 每条用户消息是否即时出现在消息列表中
   - Agent 回复是否逐条出现

**预期结果**：
- [ ] 每条用户消息 **即时** 出现在消息列表中
- [ ] Agent 回复按顺序逐条出现
- [ ] **不需要**切换 Session 才能看到新消息

**通过标准**：5 条消息全部即时显示 ✅

#### 步骤 3.2：重启后消息持久化

1. 等待所有 Agent 回复完成
2. 完全关闭应用（`Ctrl+C`）
3. 重新启动应用（`npm run dev`）
4. 打开刚才的 Session

**预期结果**：
- [ ] 所有用户消息和 Agent 回复都完整保留
- [ ] 消息顺序正确
- [ ] 无消息丢失

**通过标准**：重启后消息完整 ✅

**⚠️ 失败排查**：
- 如果重启后最后几条消息丢失：`beforeunload` flush 未生效，检查 `useChatStore` 的 `flushChatStorage()`
- 如果消息显示需要切换 Session：`debounce 100ms` 可能仍有问题，检查 `createDebouncedStorage`

## 六、常见问题排查

### Q1：Session 创建按钮点击无反应
**原因**：`isCreating` 状态卡在 `true` 未重置  
**排查**：打开 DevTools 控制台，输入 `useSessionStore.getState().isCreating`，如果为 `true`，手动执行 `useSessionStore.getState().setCreating(false)` 恢复

### Q2：流式输出完成后界面卡住
**原因**：`MessageList` 的 zustand 订阅可能被其他 state 更新覆盖  
**排查**：
1. 在 DevTools 中检查 `useChatStore.getState().messagesBySession[currentSessionId]` 是否有新消息
2. 如果有新消息但界面不更新，说明 React re-render 未触发

### Q3：重启后最后几条消息丢失
**原因**：`beforeunload` flush 未生效（Electron 中 `beforeunload` 事件可能不可靠）  
**排查**：检查 DevTools 控制台是否有 `flushStorage` 事件日志

### Q4：浏览器工具返回"浏览失败"
**原因**：
1. 网络不通或目标网站响应慢
2. CDP debugger 附加失败
3. 网页需要 JavaScript 渲染（SPA），`innerText` 提取策略可能拿到空内容  
**排查**：查看 DevTools 控制台 `[browser:open.failed]` 日志中的 error 信息

### Q5：白名单域名也无法访问
**原因**：白名单校验在主进程 IPC handler 中执行，检查 `BROWSER_DOMAIN_WHITELIST` 常量  
**排查**：在 DevTools 控制台查看 `[browser:open.request]` 日志，确认 URL 已传入

### Q6：浏览器窗口在任务栏闪烁
**原因**：隐藏窗口配置 `show: false` 未生效，或 `BrowserWindow` 创建时焦点被抢占  
**排查**：检查 `BrowserCDPService` 中 `new BrowserWindow({ show: false })` 是否正确配置
