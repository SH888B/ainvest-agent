## 三、详细测试步骤

### TC-01：Embedding 配置与基础链路（P0）

**目标**：验证设置页 Embedding 配置项存在，且基础向量生成工作正常。

#### 步骤 1.1：检查设置页 Embedding 配置
1. 打开应用，点击顶部或侧边栏的**设置入口**
2. 找到"大模型配置"区块

**预期结果**：
- [ ] 能看到"向量模型"下拉框，默认值为 `embedding-3`
- [ ] 能看到"向量维度"下拉框，默认值为 `512`
- [ ] 维度下方有小字提示："维度越高语义精度越好..."

**通过标准**：上述 3 项全部满足 ✅

#### 步骤 1.2：配置智谱 API Key
1. 在设置页填写你的**智谱 API Key**
2. 点击"验证并保存"
3. 观察验证结果

**预期结果**：
- [ ] 验证按钮可点击
- [ ] 验证通过后显示绿色"配置有效"

**通过标准**：验证通过 ✅

#### 步骤 1.3：MemoryDebugPanel 生成向量
1. 回到**聊天面板**，点击顶部标题栏右侧的 **🔧 DevTool 看板** 按钮（仅在开发环境显示）
2. 在右侧滑出的 DevTools 面板中，点击 **"向量记忆"** Tab
3. 在"Embedding 生成测试"输入框中输入：`宁德时代 Q2 财报超预期`
4. 点击"生成向量"

**预期结果**：
- [ ] 下方显示绿色结果行：
  - 维度: **512**
  - 耗时: ~100-500ms（不是几秒）
  - 前5值: 有正有负的浮点数（如 `0.0234, -0.0156, ...`）
- [ ] 控制台日志出现：`[memory:embedding.success] {dimension: 512}`

**通过标准**：维度=512，耗时<1s，值为真实浮点数 ✅

**⚠️ 失败排查**：
- 如果耗时显示 `~0ms` 且前5值有规律（如全正数），说明使用了 **fallback 伪向量**，检查 API Key 是否配置正确
- 如果报错 `fetch failed`，检查网络是否能访问 `open.bigmodel.cn`

### TC-02：记忆归档（自动 + 手动）（P0）

**目标**：验证对话结束后记忆能正确归档到 Vectra 和 memory.json。

#### 步骤 2.1：创建测试 Session 并对话
1. 在聊天面板新建一个 Session
2. 依次发送以下消息（模拟真实对话）：

```
用户：我比较激进，偏好高风险高回报
用户：帮我看看宁德时代这只股票
用户：新能源板块最近怎么样
用户：我想学一下量化交易策略
```

3. 观察 Agent 是否正常回复（不要求回复内容准确，只要流程正常）

#### 步骤 2.2：手动归档当前 Session
1. 查看右侧 Session 列表底部
2. 找到"归档当前会话"按钮，点击它
3. 观察按钮状态和日志

**预期结果**：
- [ ] 点击后按钮状态变化（如显示"归档中..."然后"已归档 ✓"）
- [ ] DevTools 控制台出现 `[memory:archive.complete]` 日志
- [ ] 日志中 `newFragments` > 0，`vectorRecords` > 0

**通过标准**：日志中 `vectorRecords` > 0 ✅

#### 步骤 2.3：验证显式偏好已保存
1. 打开设置页 → "个人偏好"标签（或记忆管理页）
2. 查看显式偏好区域

**预期结果**：
- [ ] `风险偏好` 显示为"激进"（或根据对话内容提取的值）
- [ ] `关注板块` 包含"新能源"

**通过标准**：偏好正确提取 ✅

#### 步骤 2.4：增量归档验证
1. 回到刚才的 Session，**继续发送 2 条新消息**：

```
用户：再帮我看看比亚迪
用户：谢谢
```

2. 再次点击"归档当前会话"
3. 观察日志

**预期结果**：
- [ ] `[memory:archive.complete]` 日志中 `newFragments` ≈ 2（只有新增消息被提取）
- [ ] `skippedDuplicates` 可能 > 0（如果比亚迪和宁德时代被识别为相似内容）

**通过标准**：增量归档，不重复处理旧消息 ✅

## 五、常见问题排查

### Q1：生成向量时显示 fallback 伪向量（值有规律、全正数）
**原因**：API Key 未配置或配置错误，或网络不通  
**排查**：
1. 检查设置页 API Key 是否已保存
2. 在 DevTools Network 面板查看是否有 `embeddings` 请求
3. 检查请求返回状态码（401=Key 错误，403=权限不足，200=正常）

### Q2：语义检索返回空结果
**原因**：
1. 尚未归档任何记忆（需要先 TC-02）
2. 查询文本与记忆内容差异太大
3. 向量维度不一致（如先存了 512 维，后改为 256 维）  
**排查**：先确认 MemoryDebugPanel 的"索引统计"中 `itemCount` > 0

### Q3：维度切换后旧记忆无法检索
**原因**：v5.1 当前实现中，维度切换**不会自动重建索引**（这是一个已知缺口）  
** workaround**：手动删除 `userData/ainvest/vector-memory/` 目录，重启应用

### Q4：控制台出现 `wasm-unsafe-eval` CSP 报错
**原因**：浏览器缓存了旧的 `index.html`  
**解决**：完全重启应用（`Ctrl+C` → `npm run dev`），或按 `Ctrl+R` 强制刷新
