# AInvest Agent 测试计划 v1.0

> 状态：PM Review 通过，待执行
> Review 日期：2026-06-06
> 适用范围：v2 Agent 智能模块（意图识别、工具调用、LLM 回复）

---

## 一、测试目标

1. 验证 Agent 意图识别准确率 ≥ **90%**（单意图）、≥ **70%**（复合意图）
2. 验证工具参数提取准确率 ≥ **85%**
3. 验证 E2E 回复质量加权评分 ≥ **4.0/5.0**
4. 建立可复现、可回归的自动化评测体系

---

## 二、测试方法

### 2.1 分层测试策略

```
┌─────────────────────────────────────────┐
│  Layer 3: E2E 端到端测试                  │  ← 验证完整用户旅程
│  （输入 → 意图识别 → 工具调用 → LLM 回复）  │
├─────────────────────────────────────────┤
│  Layer 2: LLM 层测试                      │  ← 验证大模型分类/生成质量
│  （意图分类准确率、回复质量评分）            │
├─────────────────────────────────────────┤
│  Layer 1: 本地正则兜底测试                 │  ← 验证降级策略可用性
│  （正则覆盖率、兜底触发率）                 │
└─────────────────────────────────────────┘
```

### 2.2 各层测试方法

| 层级 | 测试方法 | 执行方式 | 频率 |
|------|---------|---------|------|
| Layer 1 | 正则评测集批量匹配 | `npx tsx test/eval/run-intent-eval.ts` | 每次代码变更 |
| Layer 2 | LLM 分类 + LLM-as-judge 评分 | 调用真实 API（温度=0，多次采样） | 每日定时 + Prompt 变更时 |
| Layer 3 | 端到端链路验证 | 评测脚本 + 人工抽检 | 发布前 |

### 2.3 LLM-as-judge 评分机制

**裁判配置**：
- 模型：`glm-5.1`（与生产环境一致）
- Temperature：`0`
- 采样次数：`3` 次取平均

**评分维度（5分制）**：

| 维度 | 权重 | 5分标准 | 1分标准 |
|------|------|---------|---------|
| 相关性 | 30% | 完全回应用户问题 | 答非所问 |
| 准确性 | 40% | 数据/事实完全正确 | 有明显错误 |
| 流畅性 | 20% | 自然、专业、简洁 | 难以理解 |
| 完整性 | 10% | 信息完整无遗漏 | 严重缺失 |

**通过阈值**：加权平均分 ≥ 4.0/5.0

## 五、评判标准

### 5.1 意图识别

| 指标 | 阈值 | 说明 |
|------|------|------|
| 单意图准确率 | ≥ **90%** | Top-1 命中 |
| 复合意图准确率 | ≥ **70%** | 所有意图全部识别 |
| Top-1 命中率 | ≥ **92%** | 不考虑置信度 |
| 正则兜底覆盖率 | ≥ **60%** | 本地正则能覆盖的场景比例 |

### 5.2 参数提取

| 参数 | 准确率 | 评估方式 |
|------|--------|---------|
| symbol | ≥ **92%** | 精确匹配（含简称→代码映射） |
| keyword | ≥ **85%** | 语义等价即通过 |
| strategyName | ≥ **80%** | 关键词包含即通过 |
| 日期范围 | ≥ **90%** | 格式正确且合理 |

### 5.3 E2E 回复质量

| 指标 | 阈值 | 评估方式 |
|------|------|---------|
| 相关性 | ≥ 4.0/5.0 | LLM-as-judge |
| 准确性 | ≥ 4.0/5.0 | LLM-as-judge |
| 流畅性 | ≥ 4.0/5.0 | LLM-as-judge |
| 完整性 | ≥ 4.0/5.0 | LLM-as-judge |
| **加权总分** | **≥ 4.0/5.0** | 权重：相关性30%+准确性40%+流畅性20%+完整性10% |

## 六、测试流程

### 6.1 日常开发流程

```
开发者提交 PR
    ↓
CI 自动执行：
  ├─ Layer 1: 正则评测（npx tsx test/eval/run-intent-eval.ts）
  ├─ TypeScript 编译检查
  └─ ESLint 检查
    ↓
通过率 ≥ 90% ? → 通过 : 阻断合并
```

### 6.2 Prompt 变更流程

```
Prompt 变更提交
    ↓
CI 自动执行：
  ├─ Layer 1: 正则评测
  ├─ Layer 2: LLM 分类评测（全量 60+ 条）
  ├─ A/B 对比：变更前 vs 变更后
  └─ 生成 diff 报告
    ↓
通过率下降 ≤ 5% ? → 通过 : 阻断合并
```

### 6.3 发布前流程

```
发布候选版本
    ↓
手动触发全量评测：
  ├─ Layer 1: 正则评测
  ├─ Layer 2: LLM 分类 + 质量评分
  ├─ Layer 3: E2E 端到端
  ├─ 人工抽检（黄金标准集 30 条）
  └─ 生成测试报告
    ↓
全部通过 ? → 发布 : 修复后重测
```

### 6.4 回归测试触发条件

| 触发条件 | 执行范围 |
|---------|---------|
| `src/renderer/services/agent/` 变更 | Layer 1 + Layer 2 |
| `src/renderer/services/llm/` 变更 | Layer 2 + Layer 3 |
| `src/renderer/services/tools/` 变更 | Layer 1 + Layer 3 |
| `src/renderer/services/agent/prompts.ts` 变更 | Layer 2（全量）+ A/B 对比 |
| 评测集本身变更 | 全量 |
| 模型配置（BaseURL/Model/Temp）变更 | Layer 2（全量） |
